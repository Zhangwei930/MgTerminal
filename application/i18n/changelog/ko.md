# 변경 로그


## [0.6.4] - 2026-09-06

### 수정
- **값 안의 빈 줄이 더 이상 문장을 둘로 자르지 않습니다** — 가져오기와 데이터베이스 전체 덤프는 INSERT를 빈 줄로 이어 붙인 뒤 그 빈 줄로 다시 나누어 실행했습니다. 메모나 설명 열에 빈 줄이 있으면 그 구분자 자체를 품게 되어, 분할이 문자열 리터럴 한가운데를 잘랐고 양쪽 모두 구문 오류였습니다. 이제 문장을 목록으로 전달하므로 경계를 복원할 필요가 없습니다
- **결과 그리드가 이전 쿼리의 데이터를 보여주지 않습니다** — 쿼리 사이에 다시 만들어지지 않으면서도 확정된 셀 편집의 덮어쓰기, 삭제된 행 목록, 열려 있는 편집기를 내부에 들고 있었습니다. 두 번째 쿼리 뒤에는 예전 덮어쓰기가 그 자리에 온 행 위에 그려져, 새 결과에 없는 값이 표시되었습니다. 페이지마다 새 결과이므로 페이지 이동에서는 늘 일어났습니다. 필터는 유지하고 정렬은 열과 함께 초기화합니다
- **테이블 설계 화면이 대상이 바뀌면 다시 읽습니다** — 열은 열릴 때 한 번만 읽습니다. 열어 둔 채 트리에서 다른 테이블을 고르면 두 번째 이름 아래 첫 번째 열이 남고, 적용하면 실제로 고른 테이블의 열을 모두 지우고 화면에 남아 있던 열을 모두 추가했습니다. SQL이 먼저 보이긴 했지만 평범한 편집처럼 제시되었습니다
- **페이징이 따옴표 안의 열 이름을 키워드로 읽지 않습니다** — 문장에 자체 정렬이 있는지 판단하려면 키워드를 훑어야 하는데, 문자열과 주석은 가렸지만 따옴표로 묶인 식별자는 가리지 않았습니다. `offset`이라는 열은 페이징이 거부되었고, `order by`라는 열은 SQL Server에 정렬 없는 OFFSET을 보냈으며, 이름 속 괄호는 중첩 깊이 계산을 어긋나게 했습니다
- **쿼리 빌더가 값의 생김새가 아니라 열 타입으로 따옴표를 결정합니다** — 숫자처럼 보이는 문자열은 늘 따옴표 없이 쓰였습니다. 텍스트 열을 `123`으로 거르면 `"code" = 123`이 되어 PostgreSQL은 거부하고 MySQL은 형 변환으로 답했으며, `007`은 "007"이 든 행을 결코 찾지 못했습니다
- **가져오기에서 추론한 열 너비가 행 한계를 넘지 않습니다** — MySQL과 MariaDB는 모든 열을 합쳐 한 행을 65535바이트로 제한하고 utf8mb4는 문자당 4바이트로 세므로, 기존의 varchar(4000)로는 넓은 열 몇 개가 한 테이블에 들어갈 수 없었습니다. 일정 너비를 넘으면 제한 없는 타입을 씁니다
- **알려진 취약점이 있는 의존성 넷을 올렸습니다** — dompurify, undici, hono는 고정해 둔 버전 자체에 취약점이 공개되었고 js-yaml은 고정되어 있지 않았습니다. 각각 3.4.15, 6.28.1, 4.13.7, 4.3.2로, 모두 같은 메이저 안이라 깨지는 변경이 없습니다. 프로덕션 의존성에서 도달 가능한 취약점은 이로써 모두 해소되었습니다

## [0.6.3] - 2026-09-06

### 추가
- **테이블 구조 시각 편집** — 테이블 생성과 변경, 열 추가·변경·삭제, 인덱스 생성과 삭제, 테이블 이름 변경과 삭제를 하나의 열 그리드에서 처리합니다. 생성된 SQL은 실행 전에 표시됩니다. SQLite는 열 타입을 바꿀 수 없으므로(테이블 재생성이 필요), 서버가 거부할 문장을 보내는 대신 그 사실을 알립니다
- **데이터 가져오기와 내보내기** — CSV·TSV·JSON을 열별 타입 추론과 함께 읽어들이고 테이블 생성도 선택할 수 있습니다. 내보내기는 CSV·JSON·INSERT에 더해 Markdown·XML·HTML을 지원합니다. 데이터베이스 전체 덤프는 모든 테이블의 정의와 행을 기록하며, 그 파일로 복원할 수 있습니다
- **SQLite와 MariaDB 지원** — SQLite는 Node 내장 드라이버로 동작하므로 따로 설치할 것이 없습니다. 서버가 아니라 이 컴퓨터의 파일이므로 호스트·포트·자격 증명이 없고 터널도 필요 없습니다. MariaDB는 MySQL과 프로토콜과 방언이 같습니다
- **페이징·필터·스크립트·쿼리 빌더** — 결과가 고정 행 수에서 끊기지 않고 페이지 단위로 도착합니다. 그리드에서 행을 바로 걸러낼 수 있습니다. 편집기는 첫 문장만이 아니라 스크립트 전체를 실행합니다. 빌더는 단일 테이블 SELECT를 선택만으로 조립해 편집기에 넘깁니다

### 수정
- **테이블 이름이 스키마를 함께 갖습니다** — 트리는 서버의 모든 스키마에 있는 테이블을 나열하지만 이름만 돌려주었고, 열·기본 키·인덱스·외래 키 조회도 그 이름만으로 걸렀습니다. 같은 이름의 테이블이 두 스키마에 있으면 하나의 항목으로 합쳐지고 메타데이터는 둘이 섞인 결과가 됩니다. 행 편집은 그것으로 WHERE를 만들기 때문에 화면의 테이블에 없는 열을 조건으로 쓸 수도 있었습니다
- **바이너리·날짜·불리언 값이 서버가 다시 읽을 수 있는 형태로 기록됩니다** — BLOB 열은 JSON 객체로 직렬화되었습니다. 열이 그것을 받아들이므로 데이터는 조용히 망가지고, 같은 값을 WHERE에 넣으면 한 행도 맞지 않습니다. 날짜는 UTC로 밀리고 MySQL의 DATETIME이 거부하는 접미사가 붙었습니다. 불리언은 어디서나 TRUE/FALSE였지만 SQL Server에는 그런 키워드가 없고 Oracle도 23c 이전에는 불리언 타입이 없었습니다. 이제 엔진별 표기로 생성합니다
- **아무 행도 바꾸지 못한 편집이 더 이상 성공으로 보고되지 않습니다** — 기본 키가 어떤 행과도 맞지 않는 UPDATE는 정상 종료됩니다. 그런데도 그리드는 입력한 값을 저장된 것처럼 보여 주었습니다. 영향 받은 행 수는 이미 완료 응답에 있었고 읽지 않았을 뿐입니다. 흔한 원인은 결과가 낡은 것입니다 — 그 행이 지워졌거나 키가 바뀐 경우입니다
- **셀을 NULL로 만들 수 있고 행을 삭제할 수 있습니다** — 셀을 비우면 빈 문자열이 저장되어, NULL 허용 열은 한 번 값이 들어가면 다시는 비울 수 없었습니다. 이제 컨텍스트 메뉴나 Ctrl/Cmd+0으로 NULL을 쓰고, 같은 메뉴에서 행을 삭제합니다
- **데이터베이스 직접 연결을 암호화할 수 있습니다** — SSH 터널을 지나지 않는 연결은 비밀번호와 모든 행을 평문으로 보냈습니다. 어떤 엔진에도 TLS 옵션이 없었고 SQL Server는 암호화가 꺼진 채로 고정되어 있었기 때문입니다. 이제 세 가지 모드가 있으며 기본값은 여전히 꺼짐이라, 저장된 연결의 동작은 그대로입니다
- **호스트 간 전송이 공용 임시 디렉터리를 쓰지 않습니다** — 호스트 간 복사는 파일 전체를 먼저 로컬에 내려받는데, 그 중계 파일이 시스템 공용 임시 디렉터리의 예측 가능한 경로에 기록되어 같은 컴퓨터의 누구나 읽을 수 있었고, 업로드가 실패하면 그대로 남았습니다. 이제 앱 자체의 0700 디렉터리를 쓰고 실패 시에도 지웁니다
- **키를 직접 붙인 호스트도 자격 증명 상태 점검에 포함됩니다** — 이 점검은 호스트에 없는 필드를 읽었기 때문에 그런 호스트는 한 번도 검사되지 않았고, 키를 복호화하지 못할 때 "모든 인증 방식이 실패했습니다"가 표시되었습니다. 바로 이 점검이 막으려던 오해를 부르는 메시지입니다

## [0.6.2] - 2026-08-01

### 새 기능
- **데이터베이스 구조 트리**: 테이블, 뷰, 저장 프로시저, 함수, 트리거를 표시합니다. 테이블을 펼치면 컬럼·인덱스·외래 키가 보이고, CREATE TABLE도 한 번의 클릭으로 확인할 수 있습니다. MySQL과 Oracle은 서버 자체 DDL을 반환하지만 PostgreSQL과 SQL Server는 그런 기능이 없어 카탈로그에서 재구성하며, 무엇이 빠졌는지 맨 앞에 밝힙니다
- **SQL 자동 완성**: 연결된 데이터베이스의 테이블·컬럼 이름을 완성합니다. `p.` 뒤에서는 해당 테이블의 컬럼만 제안하며, FROM과 JOIN에 붙인 별칭도 해석합니다
- **결과를 그 자리에서 편집**: 셀을 더블클릭해 값을 바꾸면 원본 테이블에 대한 UPDATE가 됩니다. 쿼리가 정확히 한 테이블만 읽고, 그 테이블에 기본 키가 있으며, 결과에 기본 키 컬럼이 포함될 때만 편집할 수 있습니다. 아니면 읽기 전용으로 두고 셋 중 무엇이 빠졌는지 알려줍니다
- **트랜잭션 제어**: 자동 커밋을 끄면 직접 커밋하거나 롤백할 수 있어, DELETE 결과를 확인한 뒤 확정할 수 있습니다. 자동 커밋을 다시 켜면 커밋되지 않은 변경을 먼저 롤백하며, 이 동작을 컨트롤에 표시했습니다
- **실행 계획**: 실행 버튼 옆에서 쿼리의 실행 계획을 볼 수 있습니다. SELECT에만 제공됩니다 — SQL Server는 배치를 실행해 계획을 만들고 PostgreSQL의 EXPLAIN ANALYZE는 문을 실제로 실행하므로, 계획을 보는 일이 쓰기로 바뀌는 일은 없습니다
- **쿼리 기록과 즐겨찾기**: 실행한 문을 연결별로 기록하고, 검색해 편집기로 되돌릴 수 있습니다. 실패한 문도 남습니다. 즐겨찾기한 쿼리는 개수 제한에 밀려나지 않고 기록 지우기로도 사라지지 않습니다
- **관계도와 구조 비교**: ER 다이어그램은 의존 깊이에 따라 테이블을 배치하고 자기 참조와 순환 외래 키도 올바르게 처리합니다. 구조 비교는 저장된 다른 연결을 읽어 정렬 스크립트를 만들며, 그중 실행 가능한 것은 추가 계열 문뿐입니다. 삭제·타입 변경·NOT NULL 강화는 모두 주석으로 나옵니다
- **결과 내보내기**: CSV, JSON, INSERT 문으로 저장할 수 있습니다. CSV는 RFC 4180을 따르고 UTF-8 BOM을 붙여 Excel에서 한글이 깨지지 않으며, `=`, `+`, `-`, `@`로 시작하는 값은 Excel이 수식으로 실행하지 않도록 무력화합니다

### 수정
- **직접 연결이 이제 연결되고, 터널 연결은 실제로 터널을 지나갑니다**: SSH 터널을 쓰지 않는 연결은 작업 공간을 열자마자 "호스트를 찾을 수 없음"으로 실패했고 패킷 하나 나가지 않았습니다. 같은 코드가 호스트 ID를 백엔드에 전달하지 않아, 배스천을 지정한 연결이 실제로는 데이터베이스로 직접 접속했습니다. 데이터베이스가 배스천에서만 닿는 경우엔 이해하기 어려운 실패이고, 양쪽 다 닿는 경우엔 더 나쁩니다. 터널 밖에서 조용히 연결이 성립하기 때문입니다
- **저장한 비밀번호가 다시 읽히지 않게 되는 문제를 고쳤습니다**: 암호화 성공을 곧 정상 동작의 증거로 삼고, 암호문을 다시 복호화할 수 있는지는 한 번도 확인하지 않았습니다. macOS 키체인은 앱 서명 신원이 바뀌면 복호화는 거부하면서 암호화는 계속하므로, 비밀번호가 다시는 읽을 수 없는 형태로 기록되었고 나중에 "분명히 제대로 입력한" 연결에서 비밀번호 오류로 나타났습니다. 이제 암호화 직후 바로 읽어와 비교하고, 맞지 않으면 로컬 보관소로 대체합니다
- **SQL Server의 트랜잭션이 동작하지 않았습니다**: 이 연결은 크기를 지정하지 않은 커넥션 풀(기본 10개)이어서 `BEGIN TRANSACTION`과 이후 문이 서로 다른 연결에 배정되었습니다. 작업이 트랜잭션에 들어가지 않았고 `COMMIT`은 커밋할 것이 없었습니다. 이제 단일 연결로 고정했습니다
- **JSON 컬럼 값이 더 이상 `[object Object]`로 기록되지 않습니다**: json/jsonb 컬럼은 파싱된 객체로 돌아오는데, 이를 문자열로 만들어 쓰면 컬럼은 기꺼이 받아들이면서 데이터는 망가지는 값이 되었습니다. 이제 JSON으로 직렬화합니다

## [0.6.1] - 2026-08-01

### 수정
- **데이터베이스 연결을 저장해도 기존 연결을 덮어쓰지 않습니다**: 저장된 연결을 읽을 때 각 비밀번호를 메인 프로세스 왕복으로 복호화하는데, 그 전에 새 연결을 저장하면 빈 목록에 추가되어 저장된 전체를 대체했고 진행 중이던 읽기는 스스로를 만료로 판단해 버렸습니다. 이제 읽기가 끝나기 전에는 디스크에 쓰지 않습니다
- **연결에 실패한 데이터베이스가 "연결 중"에서 멈추지 않습니다**: SSH 터널을 만들 수 없을 때 발생하는 예외가 처리되지 않아 화면이 아무 설명 없이 무한정 대기했습니다. 인증 실패, 터널 실패, 닫힌 포트 등의 원인이 표시됩니다

### 개선
- **AI 승인 카드에 전체 SQL 문이 표시됩니다**: 쓰기 SQL 실행을 요청할 때 문장이 접힌 인수 JSON 안에만 있었습니다. 이제 셸 명령처럼 카드 제목 줄에 표시되며, 전용 데이터베이스 아이콘이 붙고 오해를 부르는 `$` 프롬프트는 붙지 않습니다

- **팀 Vault 가져오기가 더 이상 거짓 성공을 알리지 않습니다**: 공유 패키지를 가져오면 "호스트 N대를 가져왔습니다"라고 알리면서도 호스트를 버려 목록이 그대로였습니다. 이제 실제로 Vault에 기록하고 실제로 추가된 개수를 보고하며, 추가만 할 뿐 로컬 변경이나 자격 증명을 덮어쓰지 않습니다
- **WAN 초대 코드로 참여할 수 있습니다**: UI가 받아들인다고 명시했는데도 `magies-follow:2:` 초대는 항상 LAN으로 해석되어 `version` 오류가 났습니다. 이제 초대 버전으로 전송 방식을 고릅니다
- **호스트 내보내기가 선택을 따릅니다**: 일부만 선택해도 전체가 내보내졌습니다
- **긴 메뉴 레이블이 더 이상 넘치지 않습니다**: 고정 너비 때문에 가장 긴 항목이 메뉴 밖으로 밀려나고 아이콘이 0폭으로 찌그러졌습니다. 정렬 메뉴는 프랑스어에서 세 항목이 넘쳤습니다
- **tmux 명령 보내기를 쓸 수 있습니다**: UI가 제공할 수 없는 창 번호를 요구해, 기능은 있어도 실행할 수 없었습니다

### 개선
- **SFTP 전송에 남은 시간 표시**: 속도를 알 수 없으면 자리를 차지하지 않고, 총량을 파일 수로 세는 디렉터리 행에서는 표시하지 않습니다
- **상단 바에 동기화 신선도 표시**: 패널을 열지 않아도 데이터가 마지막으로 실제 반영된 시점을 확인할 수 있습니다
- **AI 대화 내보내기가 추론 과정을 유지**: Markdown에서는 접어서, 일반 텍스트에서는 들여써서 소요 시간과 함께 남깁니다
- **AI 설정 사용성**: 빠른 메시지에 검색을 추가했고, 로컬 모델에서 도구 호출이 감지되지 않을 때 그 의미를 설명합니다
- **크래시 보고의 전송량 표시**: 업로드에 성공한 경우에만 세므로 실패나 중복은 포함되지 않습니다
- **프로세스와 tmux 작업에 앱 내 대화상자 사용**: 시스템 기본 창을 쓰지 않고 앱 테마를 따릅니다
- **모바일을 품질 게이트에 포함**: `mobile/`은 lint와 테스트에서 완전히 제외되어 있었고, 그 테스트는 CI에서 한 번도 실행된 적이 없었습니다

- **JSON 호스트 소스**: 로컬 JSON 파일 또는 HTTP(S) 엔드포인트에서 호스트 인벤토리 가져오기(CMDB / Ansible / 커스텀 API 스타일). 메타데이터 전용이며 비밀 정보가 포함된 인벤토리는 거부, HTTP 인증 헤더 지원
- **호스트 인벤토리 공유 및 가져오기**: 팀 인수인계를 위한 메타데이터 전용 인벤토리 내보내기(Ansible YAML 형식 포함), 클립보드에서 가져오기
- **이름 있는 워크스페이스 템플릿**: 호스트 바인딩, 분할 레이아웃, 선택적 cwd/시작 명령을 템플릿으로 저장하고 빠른 전환기에서 원클릭 적용
- **연결 로그 북마크**: 재생 위치 북마크 + 메모 + 검색 이동, 로그 목록에 북마크 수 표시
- **포트 포워딩 실시간 채널 보기**: 로컬/원격/동적 포워딩의 연결별 소스, 대상, 트래픽 바이트 통계
- **스크립트 onOutput 트리거 동작 확장**: 출력 패턴이 일치하면 데스크톱 알림, 알림음, 탭 마커, 세션 녹화 시작 선택 가능
- **안전 붙여넣기와 정밀 브로드캐스트**: 여러 줄 붙여넣기 지연 / 프롬프트 대기 / 위험 명령 확인. 브로드캐스트는 워크스페이스/선택/그룹/창을 정확히 지정 가능
- **시스템 OpenSSH 채널 강화**: GSSAPI/Kerberos 및 포스트 양자(PQ) 알고리즘을 시스템 OpenSSH를 통해 지원; 점프 체인 및 HTTP/SOCKS 프록시 지원
- **내장 ssh2 하이브리드 포스트 양자 KEX**: `mlkem768x25519-sha256`(ML-KEM-768 + X25519)을 우선 협상하고, 서버 미지원 시 고전 알고리즘으로 폴백; 시스템 ssh 강제 불필요
- **RDP 호스트 지원**: Vault 호스트에서 RDP를 활성화하고 시스템 원격 데스크톱 클라이언트(Windows mstsc / macOS Windows App / Linux xfreerdp) 실행
- **변경 로그가 UI 언어를 따름**: 앱 내 Changelog를 현재 UI 언어로 표시(10개 언어)

## [0.4.5] - 2026-07-15

### 수정
- **중첩 암호문으로 인한 401 / 빈 스트림**: 키체인 장애 중 반복 저장하면 키가 여러 겹으로 암호화됨(`enc:v2(enc:v1(...))`). 복호화 루프 경계 수정 후 허용 범위 내 다층 중첩을 완전히 복호화, "올바르게 복호화하고 버리기"나 복호화 실패 오보가 사라짐

- **웹 검색 API 키**: 복호화 실패 후 포커스/블러만으로 저장된 키가 잘못 삭제되지 않음. 복호화/암호화 실패의 명확한 알림 추가, 더 이상 조용히 넘어가지 않음
- **Windows DPAPI 암호문 인식 수정**: 이중 암호화 방지 가드가 DPAPI 키(`AQAAAN` 헤더)를 놓쳐 키체인 장애 시 중첩 암호문으로 재암호화되던 문제 수정
- **Cursor Agent**: 복호화 실패 시 암호문을 API 키로 자식 프로세스에 주입하지 않음
- 설정의 Provider / 웹 검색 / Cursor 세 곳 통일: 복호화 실패 시 키 재입력을 명확히 안내, UI 언어 전환이 저장되지 않은 키를 덮어쓰지 않음

- 수동 "업데이트 확인"은 GitHub API로 버전을 감지, 업데이트 발견 시 비동기로 electron-updater 다운로드 트리거
- 설정 창에서 "업데이트 확인" 클릭 후 다운로드 진행률이 UI에 실시간 반영

- 새 버전 발견 후 자동 다운로드 시작(`autoDownload=true`)
- 다운로드 완료 후 지속 토스트 알림 표시, "지금 재시작" 클릭으로 설치
- 다운로드 실패 시 오류 토스트 표시, "Releases 열기" 대체 항목 제공
- Settings > System 진행률 표시줄이 자동 다운로드 진행률을 실시간 표시, `useUpdateCheck`가 일원 구동
- electron-updater 미지원 Linux deb/rpm/snap 등 플랫폼은 자동 건너뛰기, 기존 GitHub API 알림 동작 유지

### 설계 노트
- `broadcastToAllWindows`가 `getSenderWindow` 단일 전송을 대체, 모든 창이 IPC 이벤트를 수신하도록 보장
- `manualCheckStatus` 필드가 수동 확인 UI 상태(idle/checking/available/up-to-date/error)를 추적, UI 계층에서 `autoDownloadStatus`와 우선순위에 따라 렌더링
- `SettingsSystemTab`은 로컬 update state를 보유하지 않고 `useUpdateCheck` 통일 데이터를 단방향 수신
- 기존 두 독립 시스템(GitHub API 알림 + electron-updater 수동 다운로드)을 통일 상태 기계로 병합: `useUpdateCheck`가 유일한 사실 소스로 `App.tsx` 토스트와 `SettingsSystemTab` 진행률 표시줄을 함께 구동
- 전역 영속 IPC 리스너는 `autoUpdateBridge.init()`에서 한 번만 등록, 수동 다운로드 요청마다 리스너 등록/정리 반복 방지
- `autoInstallOnAppQuit=false`, 무음 설치 없이 사용자가 재시작을 직접 트리거

### 인터페이스 변경（SettingsSystemTabProps）
- 제거: `autoDownloadStatus`, `downloadPercent`
- 추가: `updateState`(전체 UpdateState), `checkNow`, `installUpdate`, `openReleasePage`

### 참고 사항
- `checkNow` 의미: GitHub API(`performCheck`)로 새 버전을 감지, 업데이트가 있고 electron-updater가 아직 다운로드를 시작하지 않았다면 비동기로 `bridge.checkForUpdate()`를 트리거해 자동 다운로드 흐름 시작
- 이 기능은 패키지된 앱(Windows NSIS, macOS dmg/zip, Linux AppImage)에서만 유효, dev 모드는 `forceDevUpdateConfig=true` + `dev-app-update.yml` 테스트 필요(`.gitignore` 참조)
- 이전 `hasUpdate` 토스트는 `autoDownloadStatus !== 'idle'` 동안 자동 억제, 새 토스트와 중복 방지

### CI / 빌드 개선
- macOS / Windows 빌드 건너뛰기(유료 코드 서명 인증서 필요), 무료 Linux 배포 패키지 제공에 집중
- Linux x64(AlmaLinux 8) 컴파일러 업그레이드: Clang 우선, gcc-toolset-13 폴백
- Linux arm64(Debian Bullseye) 컴파일러 업그레이드: `build-essential`에서 `clang-14 + lld-14`로
- Release 작업이 macOS/Windows 빌드에 의존하지 않고, tag 푸시 후 Linux 산출물 기반으로 직접 Release 게시
- deb 산출물 검증 완화: 파일을 찾지 못하면 error 대신 warning 출력, 플랫폼 건너뛰기로 인한 CI 실패 방지
